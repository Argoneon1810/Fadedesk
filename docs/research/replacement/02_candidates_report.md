## 1. 조사 결론 요약

Chrome 웹 스토어 및 GitHub 오픈소스 생태계를 전수 조사하고 실제 소스 코드(`manifest.json`, 팝업 UI, 오디오 훅 코드)를 대조한 결과, **확정된 필수 조건(타협 불가 항목)을 모두 충족하는 무료·오픈소스 확장프로그램은 현재 존재하지 않는다(0건).**

현재 브라우저 확장 생태계는 아래 **세 개의 단절된 영역**으로 쪼개져 있다.

1. **멀티탭 미디어 허브류** (`Global Speed`, `GMC-Enhance`): 여러 탭의 재생/일시정지와 탭 이동은 잘 되지만, 멀티탭 화면에서 **비-`tabCapture` 기반 볼륨 증폭(>100%)·도메인 볼륨 기억·Solo**가 빠져 있다.
2. **비-`tabCapture` 멀티탭 볼륨 슬라이더류** (`TJ Volume Mixer`): 여러 탭의 볼륨·부스트(`0~600%`)는 되지만, **재생/일시정지·탭 이동·Solo가 아예 없고**, 같은 도메인 탭 2개를 열면 볼륨이 강제로 함께 바뀌는 구조적 한계가 있다.
3. **정밀 dB/WebAudio 부스터류** (`Chaython/volumecontrol`): `tabCapture` 없는 dB 스케일 증폭(`-32~+32 dB`)·도메인 기억·피크 미터 완성도는 매우 높으나, **오직 현재 보고 있는 탭 1개만 조작**할 수 있고 재생 제어가 없다.

## 3. 근접 후보 4종 상세 분석 (타협 가능성 검토용)

만약 직접 만들지 않고 기존 도구를 쓰려 한다면 아래 4가지 중 하나(또는 조합)로 큰 타협을 해야 한다.

### 후보 1: Global Speed ([GitHub](https://github.com/polywock/globalSpeed))
- **강점**: 완성도와 안정성이 높고(★2,847), 팝업 하단 미디어 뷰에서 모든 탭의 영상/오디오 재생·일시정지, 탐색바, `0~100%` 볼륨, 음소거, 탭 포커스 이동을 한 번에 처리할 수 있다.
- **포기해야 하는 것**:
  1. 멀티탭 카드에서는 볼륨이 `0~100%`까지만 10% 단위로 조절되며, **100% 초과 증폭을 쓰려면 해당 탭으로 이동해 `tabCapture`를 켜야 한다**(파란 녹화 아이콘 발생).
  2. Solo 기능이 없고, 주 목적이 '배속 제어기'라 상단 절반을 배속 UI가 차지하며, 원격 자체 홍보 배너(`SelfPromo`) 통신 코드가 들어 있다.

### 후보 2: TJ Volume Mixer ([GitHub](https://github.com/TueJon/tj-volume-mixer) · [Chrome 웹 스토어](https://chromewebstore.google.com/detail/tj-volume-mixer/ffpakgdgibapcfmbafhignoknlhggopm))
- **비고(검색 노출 관련)**: 2026-11-09에 v2.0.0이 푸시된 GitHub ★0 신생 저장소라 일반 포털·스토어 키워드 검색에서는 상위에 잡히지 않는다(위 직접 URL 둘 다 HTTP 200 실존 확인 완료).
- **강점**: 깔끔한 MIT 오픈소스로, `tabCapture` 없이 팝업에서 미디어가 있는 모든 탭을 모아 `0~600%` 볼륨 조절과 음소거를 즉시 수행한다.
- **포기해야 하는 것**:
  1. **재생/일시정지 버튼과 탭 포커스 이동 버튼, Solo 버튼이 아예 없다**(순수 볼륨 슬라이더 목록만 존재).
  2. 볼륨이 도메인(`origin`) 단위로만 묶여 있어 **유튜브 탭을 2개 열어 두고 한쪽 볼륨을 바꾸면 다른 유튜브 탭 볼륨까지 동시에 똑같이 바뀌어 버린다.**

### 후보 3: GMC-Enhance ([GitHub](https://github.com/ZepengW/GMC-Enhance) · [Chrome 웹 스토어](https://chromewebstore.google.com/detail/kibmlbbigjmpmfjpcjhlmimehchnamgi))
- **강점**: `tabCapture` 없이 모든 탭의 재생/일시정지·탐색·음소거·`0~100%` 볼륨과 탭별 10밴드 이퀄라이저·실시간 주파수 스펙트럼을 지원한다(GPL-3.0).
- **포기해야 하는 것**:
  1. 직관적인 100% 초과 볼륨 증폭 슬라이더가 없고, 도메인별 볼륨 기억 기능과 Solo 기능이 없다.
  2. 팝업 인터페이스가 중국어 간체로 하드코딩되어 있다.

### 후보 4: Volume Control ([GitHub](https://github.com/Chaython/volumecontrol))
- **강점**: 오디오 처리 품질만 놓고 보면 가장 이상적이다. `tabCapture` 없이 `-32 dB ~ +32 dB` 데시벨 페이더, 사이트별 볼륨 기억(미저장 탭 독립 유지), 노멀라이저, 출력 피크 미터를 모두 갖췄다(ISC 라이선스).
- **포기해야 하는 것**:
  1. **중앙 멀티탭 패널이 아니다.** 오직 지금 보고 있는 탭 1개의 볼륨만 조절하며, 백그라운드 탭 목록·재생/일시정지·Solo·탭 이동이 전혀 없다.

## 4. 보류 항목 쉬운 해설: "CORS란 무엇이고, 왜 `+dB` 증폭과 관계가 있는가?"

2차 인터뷰에서 보류했던 **CORS(교차 출처 리소스 공유) 제약**을 비전문가 관점에서 실제 현상 위주로 정리한다.

### 4.1 무슨 현상인가?
웹사이트가 영상을 재생할 때 두 가지 경우가 있다.
1. **같은 집(또는 허락증을 붙여 준 창고)에서 영상을 가져오는 경우** — 유튜브, 치지직, 트위치, 사운드클라우드, 대부분의 대형 스트리밍·웹 오디오 사이트.
2. **남의 서버에 있는 영상 파일 주소만 허락증 없이 그대로 끌어다 틀어 놓은 경우** — 일부 커뮤니티 게시글이나 외부 링크 직결 `<video>` 태그, 그리고 넷플릭스 같은 **강력한 불법복제 방지(DRM)** 영상.

Chrome 브라우저는 보안상 **"2번(허락증 없는 외부 영상·DRM 영상)의 소리 데이터를 페이지 내부 스크립트가 가로채서 가공(증폭·이퀄라이저·파형 측정)하지 못하게"** 막아 두었다. 만약 확장프로그램이 무작정 증폭기(`WebAudio`)를 꽂으면 Chrome이 보안 규칙에 따라 그 영상의 소리를 아예 **무음(0)** 으로 만들어 버린다.

### 4.2 실제로 체감되는 차이 (표)

| 기능 | 유튜브 · 치지직 · 트위치 · 일반 웹 오디오 (대다수 사이트) | 일부 외부 직결 영상 / 넷플릭스 등 DRM 영상 (예외 사이트) |
|---|---|---|
| 재생 / 일시정지 / 탭 이동 | 정상 동작 | 정상 동작 |
| 음소거(Mute) / Solo | 정상 동작 | 정상 동작 |
| 볼륨 줄이기 (`-∞ dB ~ 0 dB`, 0~100%) | **정상 동작** | **정상 동작** *(기본 볼륨 속성 사용)* |
| **볼륨 키우기 (`+dB` 증폭, 100% 초과)** | **`tabCapture` 없이도 정상 증폭 가능!** | `tabCapture` 없이는 **원본 최대 크기(`0 dB` = 100%)까지만 가능** |

### 4.3 기존 검증된 오픈소스(`Chaython/volumecontrol`, `TJ Volume Mixer`)의 해결법
오늘 코드로 확인한 두 오픈소스 확장 모두 똑같은 정석 해법을 쓰고 있었다.
- **평소(`0 dB` 이하로 줄이거나 음소거할 때)**: 브라우저 기본 볼륨 기능을 쓰므로 **모든 사이트에서 100% 안전하게 동작**한다.
- **`+dB` 증폭을 올릴 때**: 증폭기 연결이 가능한 사이트(유튜브 등 대다수)에서는 즉시 `+dB` 증폭을 적용하고, 보안(CORS/DRM)으로 막힌 예외 영상임이 감지되면 **소리가 먹통이 되지 않도록 자동으로 `0 dB`(원본 100%)에서 상한을 멈춘 뒤 화면에 작게 "이 영상은 브라우저 보안 정책상 원본 크기(0 dB)까지만 지원됩니다"라고 안내**한다.

따라서 우리가 직접 제작하더라도 아래와 같이 두 가지 선택지 중 하나만 고르면 깔끔하게 해결된다.
- **선택지 A (권장 — 완전한 비-`tabCapture` 유지)**: `Chaython/volumecontrol` 방식처럼 `tabCapture` 권한을 아예 넣지 않고, 보안 제한 영상만 안전하게 `0 dB`(100%) 상한으로 자동 보호 + 배지 표시.
- **선택지 B (하이브리드 — 평소 비-`tabCapture` + 수동 비상 버튼)**: 평소에는 `tabCapture`를 전혀 쓰지 않다가, 보안 제한 영상인데 소리가 너무 작아 꼭 키워야 할 때만 사용자가 직접 누를 수 있는 `[강제 증폭]` 보조 버튼을 둠.

## 5. 사용자 적합성 인터뷰 결과 및 최종 기각 사유 (2026-11-12)

후보 검토 결과 모든 기존 대안을 기각하고 **직접 제작 단계([01_ux_briefing.md](../../design/01_ux_briefing.md))로 전환**하기로 확정했다.

1. **Global Speed 기각**: GUI가 투박해 사용성이 떨어지며, 확장프로그램의 주 정체성이 볼륨 믹싱이 아닌 재생속도 제어에 치우쳐 있음.
2. **TJ Volume Mixer 기각**: 신생 저장소(★0)라 일반 검색으로 접근하기 어렵고, 기능적으로도 재생/일시정지·탭 이동·Solo 부재 및 동일 도메인 탭 간 볼륨 강제 연동 문제가 있어 부적합.
3. **GMC-Enhance 기각**: 각 탭이 세로 리스트 아이템(가로형 카드)으로 쌓이고 조작부가 불필요하게 비대(bulky)함. 의도하는 형태는 리스트 카드가 아니라 **슬림한 오디오 채널 스트립 형태(VoiceMeeter 느낌의 콘솔 채널 배열)**임.
4. **Volume Control 기각**: 단일 활성 탭 전용 도구라 멀티탭 중앙 제어 의도와 거리가 멂.
5. **CORS/DRM 예외 처리 확정**: `tabCapture` 권한은 아예 사용하지 않고, 보안 제한(DRM·외부 무허가 직결) 예외 영상만 자동으로 `0 dB`(원본 100%) 상한으로 보호 및 소형 안내 표시(선택지 A 확정).
